# Building StreamDock plugins

This is a practical introduction to StreamDock plugin development, based on the
official MiraBox SDK templates and the architecture used by this project. The
examples use Node.js because it makes WebSocket integrations straightforward.

Official references:

- [MiraBox StreamDock Plugin SDK](https://github.com/MiraboxSpace/StreamDock-Plugin-SDK)
- [StreamDock SDK documentation](https://sdk.key123.vip/en/)

## Mental model

A StreamDock plugin is a directory whose name ends in `.sdPlugin`. Its
`manifest.json` declares the plugin, actions, supported controller types,
icons, and executable entry point.

StreamDock starts one plugin process and passes connection arguments to it. The
process opens a local WebSocket to StreamDock and registers itself. Every action
placed on a device gets its own opaque `context`. Keep per-button state keyed by
that context; do not assume that an action exists only once.

Common incoming events include:

- `willAppear`: an action instance became visible;
- `willDisappear`: it was removed or is no longer visible;
- `keyUp`: a normal LCD key was released;
- `touchTap`: a touch/information surface was tapped, when supported;
- `didReceiveSettings`: per-action settings changed;
- `didReceiveGlobalSettings`: shared plugin settings changed.

Common outgoing events include `setTitle`, `setImage`, `setState`,
`setSettings`, `setGlobalSettings`, and `openUrl`.

## Controllers and HSV293-S Info Board

Use `"Controllers": ["Keypad"]` for pressable LCD keys. On the HSV293-S, the
right-side Info Board behaves as separate `Information` slots, so a display
action should include `"Information"`. It is not one large pressable key, and a
single action cannot be assumed to span the full vertical panel.

Controller behavior differs between StreamDock models and software versions.
Treat `Information` and `SecondaryScreen` support as device-specific, test on
real hardware, and keep destructive controls such as Start/Stop Stream on a
normal `Keypad` action.

## Minimal timer plugin

The following timer starts or pauses when its key is pressed. Each placed timer
has independent state. It updates only when the displayed second changes, which
keeps WebSocket traffic and rendering work small.

### Directory layout

```text
timer-plugin/
  package.json
  src/
    index.js
  com.example.streamdock.timer.sdPlugin/
    manifest.json
    plugin/
      index.js                 # generated by the build
    static/
      icon.png
      key.png
```

Create 144×144 PNG images for `icon.png` and `key.png`. The plugin bundle is the
entire `com.example.streamdock.timer.sdPlugin` directory.

### `package.json`

```json
{
  "name": "streamdock-timer-example",
  "version": "1.0.0",
  "private": true,
  "scripts": {
    "check": "node --check src/index.js",
    "build": "ncc build src/index.js -m -o com.example.streamdock.timer.sdPlugin/plugin"
  },
  "dependencies": {
    "ws": "^8.18.3"
  },
  "devDependencies": {
    "@vercel/ncc": "^0.38.3"
  }
}
```

Bundling with `ncc` puts the WebSocket dependency into the generated file, so
users do not need to install packages inside the plugin directory.

### `src/index.js`

```js
const WebSocket = require("ws");

function argument(name) {
  const index = process.argv.indexOf(name);
  return index >= 0 ? process.argv[index + 1] : undefined;
}

// Current StreamDock versions pass named arguments. The positional fallback
// also works with older SDK templates.
const port = argument("-port") || process.argv[2];
const pluginUUID = argument("-pluginUUID") || process.argv[3];
const registerEvent = argument("-registerEvent") || process.argv[4];

if (!port || !pluginUUID || !registerEvent) {
  throw new Error("Missing StreamDock launch arguments");
}

const socket = new WebSocket(`ws://127.0.0.1:${port}`);
const timers = new Map();

function send(event, context, payload = {}) {
  if (socket.readyState !== WebSocket.OPEN) return;
  socket.send(JSON.stringify({ event, context, payload }));
}

function format(seconds) {
  const value = Math.max(0, seconds);
  const minutes = Math.floor(value / 60);
  return `${minutes}:${String(value % 60).padStart(2, "0")}`;
}

function render(context, timer) {
  const elapsed = timer.running
    ? Math.floor((Date.now() - timer.startedAt) / 1000)
    : 0;
  const remaining = Math.max(0, timer.remainingAtStart - elapsed);

  if (remaining !== timer.lastRendered) {
    timer.lastRendered = remaining;
    send("setTitle", context, {
      target: 0,
      title: `TIMER\n${format(remaining)}`
    });
  }

  if (remaining === 0) {
    timer.running = false;
    timer.remainingAtStart = 60;
  }
}

socket.on("open", () => {
  socket.send(JSON.stringify({ event: registerEvent, uuid: pluginUUID }));
});

socket.on("message", raw => {
  const message = JSON.parse(raw.toString());
  const { event, context } = message;

  if (event === "willAppear") {
    const timer = {
      running: false,
      startedAt: 0,
      remainingAtStart: 60,
      lastRendered: -1
    };
    timers.set(context, timer);
    render(context, timer);
  }

  if (event === "keyUp") {
    const timer = timers.get(context);
    if (!timer) return;

    if (timer.running) {
      const elapsed = Math.floor((Date.now() - timer.startedAt) / 1000);
      timer.remainingAtStart = Math.max(0, timer.remainingAtStart - elapsed);
      timer.running = false;
    } else {
      if (timer.remainingAtStart === 0) timer.remainingAtStart = 60;
      timer.startedAt = Date.now();
      timer.running = true;
    }
    timer.lastRendered = -1;
    render(context, timer);
  }

  if (event === "willDisappear") timers.delete(context);
});

setInterval(() => {
  for (const [context, timer] of timers) render(context, timer);
}, 250);

socket.on("close", () => process.exit(0));
```

### Build and install

```powershell
pnpm install
pnpm run check
pnpm run build
```

Close StreamDock and copy the resulting directory to:

```text
%APPDATA%\HotSpot\StreamDock\plugins\com.example.streamdock.timer.sdPlugin
```

Start StreamDock, find **Timer Example**, and drag **Simple timer** onto a key.
Press it to start or pause the countdown. StreamDock logs are normally under
`%APPDATA%\HotSpot\StreamDock\logs\` and are the first place to check when an
action does not appear or the plugin process exits.

## Adding settings

Add a `PropertyInspectorPath` to the action when users need configuration. The
Property Inspector is an HTML/JavaScript page that uses its own StreamDock
WebSocket connection. Store action-specific values with `setSettings`; store
shared connections such as Twitch OAuth or OBS configuration with
`setGlobalSettings`. Validate every value again in the plugin process because
settings are external input.

For a configurable timer, persist `durationSeconds` per context. On
`willAppear`, read `payload.settings.durationSeconds`, fall back to 60, and use
the value when resetting the timer.

## Dynamic images and performance

`setTitle` is sufficient for the example. For dashboards, meters, avatars, or
custom typography, render an SVG or canvas image and send it with `setImage` as
a data URL. Cache the last rendered value and send an update only when pixels
would change. A shared 250 ms scheduler is usually better than one interval per
button.

Keep network clients shared at plugin level: one Twitch connection and one OBS
connection can feed every visible action. Maintain per-context display state,
unsubscribe when the last consumer disappears, use reconnect backoff, and avoid
logging credentials or complete OAuth responses.

## Production checklist

- stable and globally unique plugin/action UUIDs;
- valid icon paths and images;
- per-context cleanup on `willDisappear`;
- WebSocket reconnect and malformed-message handling;
- settings migration when schemas change;
- throttled LCD rendering;
- no Client Secret, OAuth token, OBS password, or personal profile in source or
  release artifacts;
- testing on each advertised controller and StreamDock software version;
- version synchronized between package metadata and `manifest.json`;
- a ZIP containing one installable `.sdPlugin` directory.
